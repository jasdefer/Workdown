## In plain words

A place for defects noticed while actually using workdown, as opposed
to cleanups that came out of reading the code.

Each child is a single thing that behaves wrongly and has been
reproduced. They are unrelated to each other and can be picked up in
any order. **Example:** one child is a click in the web UI that does
nothing, another is a command that fails on a project where a folder
is absent. The milestone has no schedule; it stays open and collects
whatever the next stretch of use turns up.
